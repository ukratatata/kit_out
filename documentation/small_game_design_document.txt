KIT OUT — Small Game Design Document
Last synced with implementation: June 2026

> Setting & Visuals:

- Theme: Cat-themed cartoony aesthetic.

- Perspective: 2.5D. Graphics are 3D, but player movement is strictly locked to the 2D plane (X and Y axes).

- Scenario: GAME-SHOW ARENA (decided). Theatrical obstacle-course staging in the Doritos Crash Course lineage. All future art, props, and obstacle theming follow this direction.

> Player Movement (IMPLEMENTED — scripts/player.gd):

- State machine: IDLE, RUN, SPRINT, OFF_BALANCE, JUMP, FALL, CROUCH, SLIDE.

- Movement: run speed 12 u/s, acceleration 100, ground friction 80.
  Friction decision (was open): slight inertia, not immediate stop. Momentum above
  run speed (from slides/jumps) bleeds gradually (momentum_bleed 0.35) instead of snapping.

- Sprint: x1.6 speed, 3.0 s of stamina, regen 1.5/s. Empty stamina triggers
  OFF_BALANCE: 1.2 s stumble at 30% control (jumping still allowed). The cat
  leans further forward as stamina drains — visual warning of the incoming stumble.

- Jump: velocity 20, gravity x4 (x1.3 extra while falling).
  Game-feel values (were open): coyote time 0.13 s, jump buffer 0.12 s — locked after testing.

- Wall jump: only on surfaces in the "wall_jumpable" group. Push force (14, 18).

- Crouch: hold-to-crouch, 40% walk speed, collision shape swap, works mid-air
  for tight gaps (requirement met). On flat ground crouch-walking never auto-slides.

- Slide: +4 entry boost from the ground; physics-based slope acceleration
  (gravity projected onto the slope, x1.5 arcade factor) — accelerates downhill,
  brakes hard uphill; 0.5 s entry lock, release-to-stand after; downhill slides
  are not time-limited. Landing while holding crouch converts air momentum into a slide.

- Ice: surfaces in the "ice_surface" group use friction 8 instead of 80.

- Personality: the cat always turns through the camera-facing angle on direction
  changes, and glances at the camera after 0.4 s of standing idle.

> Camera (IMPLEMENTED — scripts/camera_follow.gd):

- Follows X/Y with a deadzone, leads ahead of the player, hard-clamps both axes,
  dynamic tilt driven by state-filtered velocity (player.camera_velocity),
  trauma-based screen shake (hook: player.took_damage signal).

- TODO: flip the lead offset when running left; separate ahead/behind clamp distances.

> Obstacles & Interactions (PHASE 3 — IN PROGRESS):

- Swinging hammers — DONE (solid handle + head, both deal a stun hit, phase_offset for waves)
- Spinning bars — DONE (vertical paddle rotating on X, knocks the player OFF the track in Z)
- Collapsing platforms — DONE (trapdoor: rattle warning, hinges open downward, respawns)
- Trampolines — DONE (fall-proportional bounce, centre-of-pad bonus, cannot stand on)
- Slippery ice sections — DONE (SurfaceData system; ice friction 8, slope-slip pull)
- Wall jumping surfaces — DONE (proximity raycast detection, same-wall half-height penalty)
- Crouching through low gaps — DONE (works mid-jump)
- Skipping Rope-style hammers — NOT STARTED (variant of hammer: full 360 rotation)
- Ropes (swinging/climbing) — NOT STARTED
- Projectiles/Shooting obstacles — NOT STARTED
- Bubble-style jumping pads — NOT STARTED (one-use disappearing pad)

> Systems (built alongside Phase 3):

- Surface system: data-driven SurfaceData resources (.tres), matched by node group.
  Each defines friction, acceleration mult, max-speed mult, and slope-slip.
- Hit/stun system: HazardHandler component. apply_hit (2D) / apply_hit_3d (off-track).
  Identical knockback (velocity set, not added), stun lock, i-frames with blink.
- Checkpoint system: reusable checkpoint.tscn + GameState autoload. Self-orders by
  X position, survives scene reloads.
- Kill zone: reusable kill_zone.tscn. Falling respawns at last checkpoint (or
  restarts if none reached).
- Pause menu: Esc/P. Resume / Restart Level (clears checkpoints) / From Checkpoint.
- Player composition: split into VisualsController, SurfaceDetector, HazardHandler
  child components.

> Open decisions:

- Multiplayer: time attack ships first (race timer + best times, Phase 5);
  local split-screen considered for a later version.
- Win/loss structure, level count, and progression: to define during Phase 4-5.
- Start line / finish line / race timer: BUILT (race_gate.tscn START/FINISH +
  race_hud.tscn live timer & best time, stored in GameState).

> Phase 4-5 status (game loop):

- Race timer + best time — DONE (GameState tracks run_time / best_time).
- Start & finish gates — DONE (race_gate.tscn, mode = START or FINISH).
- Race HUD — DONE (live timer, best time, finish banner).
- Designed first level — NOT STARTED (test_level is still a sandbox).
- Main menu / level select — NOT STARTED.
- Win flow beyond the finish banner (next level, retry) — NOT STARTED.
